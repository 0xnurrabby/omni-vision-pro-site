01 / Capabilities

More than screenshot OCR.

A complete context layer for models that cannot see — from lost attachments to whole archives, everything arrives safe, ordered, and ready to use.

Attachment recovery◈

Find the image, even when your client loses it.

Resolves absolute and relative paths, file:// URLs, Markdown links, inline base64 data, OpenCode caches, and bounded temporary-folder scans automatically.

dragged-image.pngresolved + prepared
Vision routing◈

AI when configured. OCR when it is not.

Gemini Flash OpenAI · low detail Local Tesseract OCR

Cloud quota or request failures never crash the server — the image simply retries with local OCR.

Ordered batches◈

Image 1 stays image 1.

Screenshots are processed sequentially and returned with stable index delimiters. A failed image never discards the ones after it.

Index 1Index 2Index 3
Code context◈

A clean tree, then the files that matter.

Skips node_modules, .git, builds, binaries, symlinks, and common secret files before returning source.

src/├─ components/├─ lib/└─ app.ts
Safe ZIP inspection◈

Read archives without extracting a single file.

In-memory inspection with traversal, duplicate, encryption, CRC, compression-ratio, and ZIP-bomb defenses built in.

ZIP✓
Local measurements◈

Know the image before the model does.

Resized dimensions, dominant color, and a compact palette measured locally with sharp — no cloud round-trip.

02 / How it works

Local first. Cloud only when you choose it.

Every request travels the same safe pipeline: prepare once, route intelligently, return structure.

◐ Your context screenshot · folder · zip
◈ Omni prepare orient · resize · measure · guard
◉ Smart router fallback chain, never crashes
Gemini OpenAI OCR
✓ Structured context ordered JSON · file tree
  1. 01

    Prepare once

    Orientation, resize, compression, and local measurement happen before anything leaves your machine.

  2. 02

    Route safely

    Gemini, then OpenAI low-detail, then local OCR. Quota and failures fall back instead of failing.

  3. 03

    Return structure

    Text, layout, colors, hierarchy, accessibility notes — delivered as delimited blocks your model can parse.

05 / Setup docs

Start in one command. Stay in control.

The automatic installer handles everything for you — or pick your client and follow the manual guide. Both paths take under two minutes.

Fastest path

One-click setup for Codex, OpenCode, Claude Code & Cursor

Ready to run

Paste this into a supported AI chat or your terminal. Omni detects clients, installs a private version-pinned runtime, writes the MCP configuration, and verifies all three tools — without touching unrelated settings.

$ npx --yes omni-vision-pro@latest setup --yes

  2. 02Pin a private, predictable runtime version

01

Codex

CLI, desktop app, and IDE extension

Automatic setup configures the shared Codex CLI, so every Codex surface picks it up.

User-wide command

codex mcp add omni-vision-pro -- npx --yes omni-vision-pro@latest serve

Manual TOML

[mcp_servers.omni-vision-pro]
command = "npx"
args = ["--yes", "omni-vision-pro@latest", "serve"]
startup_timeout_sec = 120
tool_timeout_sec = 1200
enabled = true

Save in ~/.codex/config.toml (or a project .codex/config.toml), start a new session, then check /mcp.

02

OpenCode

Project or user configuration

Use opencode.json or opencode.jsonc. The extended timeout supports local OCR and ordered batches.

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "omni-vision-pro": {
      "type": "local",
      "command": ["npx", "--yes", "omni-vision-pro@latest", "serve"],
      "enabled": true,
      "timeout": 600000
    }
  }
}

Add it to a project config or ~/.config/opencode/opencode.json, restart OpenCode, then run opencode mcp list.

03

Claude Code

User-wide or project-only setup

Project entries live in .mcp.json and may require approval. Verify with claude mcp list.

Optional but powerful

Add AI vision: Gemini or OpenAI

OCR reads text. AI vision also describes layout, buttons, colors, hierarchy, and structure. Keys are stored in a private Omni .env — never in client configs.

From a terminal

npx --yes omni-vision-pro@latest provider

Guided menu — paste your key into a hidden prompt. Keys never enter chat text, command arguments, or shell history.

From an AI chat, safely

npx --yes omni-vision-pro@latest provider set --from-clipboard

Copy only the key, then ask your AI to run this. It recognizes the provider, saves the key, and selects it.

Manual .env file

GEMINI_API_KEY=your_key_here
# or OPENAI_API_KEY=your_key_here
# OMNI_VISION_PROVIDER=auto | gemini | openai | ocr

%APPDATA%/omni-vision-pro/.env on Windows · ~/.config/omni-vision-pro/.env on macOS/Linux

npx --yes omni-vision-pro@latest provider status
npx --yes omni-vision-pro@latest provider on
npx --yes omni-vision-pro@latest provider off
npx --yes omni-vision-pro@latest doctor

06 / Privacy

Code and ZIPs never reach a vision provider.

Only a resized image is sent to a configured vision provider. Code and ZIP contents are read locally and returned to your MCP host — which may pass context to its own model under its own policy. With no key, or with AI off, image processing stays local too.

  • ✓No filesystem extraction for ZIPs — ever
  • ✓Path traversal, symlink & ZIP-bomb defenses
  • ✓.env, id_rsa, and secrets auto-skipped
  • ✓Absolute host paths hidden by default

07 / FAQ

Questions, answered.

No. Local Tesseract OCR works immediately after setup, free of charge. Gemini or OpenAI keys are optional upgrades for richer AI vision — add them later whenever you want.

Any text-only model behind a standard MCP host: DeepSeek, Codex, OpenCode, Claude Code, Cursor, VS Code, Claude Desktop, and more. The server speaks Model Context Protocol over stdio.

Attachments are resolved from wherever your client lost them, prepared locally (orientation, resize, compression, measurement), then routed to the selected vision provider — or local OCR — with automatic fallback. The result returns as ordered, delimited context blocks.

No. Only resized images may go to a configured cloud provider. Code and ZIP contents are processed entirely on your machine and returned to your MCP host.
